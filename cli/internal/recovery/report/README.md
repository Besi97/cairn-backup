# Recovery evidence

`WriteText` and `WriteJSON` render `Evidence`; neither performs a check or stores a report. JSON has a `version` field (currently 1). The `*_display` fields are quoted Go byte literals for display only, not selectors. Archive names and paths can be sensitive even after escaping; callers must not put these reports in local run history or Borg diagnostics. Do not put credentials, assertion expected contents or digests, raw errors, or diagnostic output in evidence. Fixed reason codes identify failures without disclosing those values.

The workflow owns outcome decisions and maps selection, extraction, assertion, sample and cleanup results to evidence. Initialize every unattempted step and sample as `not_run`. Record each configured assertion with the corresponding `assertions.Result` status and reason; `ChecksState` distinguishes no checks from checks not attempted. `Sample` uses `assertions.SampleResult` codes and counts. Set `EligibleComplete` only when selection is known complete; for a failed sample, conservatively leave it false because the API does not expose which phase failed. A partial eligible count is not coverage of the whole tree. `Unselected` counts eligible paths outside the sample, and `Omitted` counts selected paths not compared. Live and restored trees are not snapshots; a comparison is not proof of archive integrity.

Populate archive name and IDs from `selection.Candidate`, not from a display string. Identity steps describe the observed ID checks before and after extraction. They cannot detect replacement and reversion or prove which archive a separate extraction command saw. `workspace.Run` reports Borg's outcome separately from callback and cleanup errors; inspect `workspace.CleanupError` without rendering its raw error or path. A process-group shutdown failure can leave a workspace behind. If cleanup was not attempted, report `not_run`, not success.

The renderer rejects unknown codes and excessive input instead of truncating evidence. Paths and names are limited to 4096 bytes each, and each list to 1000 entries; sample selection permits up to 10000 files. The workflow must handle rendering errors without silently treating an incomplete report as success. Reports disclose paths and IDs and require appropriate access controls; delivery and retention policy belong to the caller.
